# Подготовка к защите Assignment 5

## Краткое объяснение

В моей программе группа RPG-персонажей распределяет золото после подземелья. Есть три взаимозаменяемых алгоритма: поровну, пропорционально вкладу и всё игроку с максимальным вкладом. Общий интерфейс `LootStrategy` объявляет метод `distribute()`. Каждый алгоритм реализован отдельным классом.

Контекст `LootDistributor` хранит ссылку на интерфейс, проверяет входные данные и делегирует расчёт выбранной стратегии. Клиент `Main` создаёт стратегии и меняет их через `setStrategy()`. Объект контекста при этом остаётся тем же. Это Strategy — поведенческий паттерн, позволяющий менять алгоритм во время выполнения.

## Как читать код

1. `PartyMember`: имя и положительные очки вклада. После создания эти данные не меняются.
2. `LootStrategy`: общий контракт. На входе золото и группа, на выходе массив долей в порядке игроков.
3. Три класса `...Strategy`: разные способы решить одну задачу.
4. `LootDistributor`: поле `private LootStrategy strategy`, конструктор, замена стратегии и делегирование.
5. `Main`: один контекст последовательно использует три алгоритма для одинаковых входных данных.

## Пример вручную

Есть 101 монета. Вклад Alinur — 50, Madi — 30, Robin — 20.

- Поровну: каждому по 33, остаются 2 монеты. Первые двое получают по дополнительной монете. Результат: 34, 34, 33.
- По вкладу: сумма очков 100. Первый расчёт: 5050 / 100 = 50, остаток 50. Второй: (3030 + 50) / 100 = 30, остаток 80. Третий: (2020 + 80) / 100 = 21, остаток 0. Результат: 50, 30, 21.
- Лучшему участнику: максимальный вклад у Alinur. Результат: 101, 0, 0.

Во всех случаях сумма долей равна 101. Остаток при расчёте по вкладу переносится дальше, поэтому монеты не теряются. Порядок игроков влияет на округление. При равенстве максимального вклада выигрывает первый из участников с этим значением.

## Вопросы и ответы

**Почему это Strategy?** Одна задача, общий интерфейс, отдельные алгоритмы, контекст с делегированием и замена алгоритма во время работы.

**Где выбирается алгоритм?** В `Main`: клиент создаёт нужный объект и передаёт его контексту. Контекст сам алгоритм не выбирает.

**Почему в программе всё же есть if?** Запрещено ветвление по типу стратегии внутри контекста. Проверка отрицательного золота, выдача остатка и поиск максимального вклада — это проверки данных и части алгоритмов. Они не заменяют полиморфизм.

**Как добавить четвёртый способ?** Создать новый класс с `implements LootStrategy` и передать его в контекст. В папке `examples` есть рабочий пример `LeaderTakesAllStrategy` и отдельный клиент `ExtensionDemo`. Существующие классы менять не требуется.

**Какие пять принципов Clean Code использованы?** Осмысленные имена; единственная ответственность; инкапсуляция; полиморфизм вместо проверки типов; зависимость от интерфейса. Дополнительно показаны Open/Closed и небольшие методы. Для каждого можно указать конкретный класс из README.

**Почему контекст не знает конкретных классов?** Его поле имеет тип `LootStrategy`, а вызов всегда один: `strategy.distribute(gold, party)`. Конкретную реализацию выбирает Java через полиморфизм.

**Что будет при ошибочных данных?** Отрицательное золото, пустая группа, пустое имя или неположительный вклад вызывают `IllegalArgumentException`. Отсутствующая стратегия, null вместо группы или null внутри группы отклоняются через `NullPointerException`. Нулевая награда допустима.

**Почему используется long?** Произведение целочисленных gold и contribution может не поместиться в int. Приведение к long выполняется до умножения. Сумма вкладов и остаток тоже хранятся в long.

**Почему не наследовать контекст для каждого способа?** Композиция позволяет заменить стратегию у уже существующего объекта. При наследовании пришлось бы выбирать другой подкласс контекста.

**Чем отличается от Bridge из Assignment 3?** Bridge разделяет две независимо изменяющиеся стороны абстракции и реализации. Strategy выделяет взаимозаменяемые алгоритмы одной операции. Здесь нет двух иерархий персонажей и боевых стилей: есть один контекст распределения награды и семейство алгоритмов.

**Какова сложность?** Все три основных алгоритма работают за O(n), где n — число участников. Массив результата занимает O(n). Контекст дополнительно создаёт снимок списка за O(n).

**Какой недостаток у Strategy?** Появляется больше классов, а клиент должен понимать, какой алгоритм ему нужен. Для одной неизменяемой формулы такой паттерн может быть избыточным.
